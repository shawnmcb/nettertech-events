## Maintainability

### INV-M1 — Quality gates demonstrably measure (planted-probe test)
- **statement:** A planted type-error probe file causes `composer phpstan` to exit non-zero. A gate that exits 0 on a known-bad input is dead, not passing.
- **source:** ISO/IEC 25010:2023 Maintainability — Testability; Ford/Parsons/Kua fitness-function discipline
- **fitness_function:**
  - categorization: triggered, atomic, static
  - test: `bash -c 'trap "rm -f includes/CoherenceProbe.php" EXIT; printf "<?php\ndeclare(strict_types=1);\nnamespace NetterTechEvents;\nclass CoherenceProbe { public function probe(): int { return \"not-an-int\"; } }\n" > includes/CoherenceProbe.php; if composer phpstan >/dev/null 2>&1; then exit 1; else exit 0; fi'`
  - expected_exit: 0
- **adr:** ADR-018 (pending, consolidated, before 1.1.1 — include why the probe runs in pre-push, not pre-commit)
- **owner:** maintainer
- **failure_mode:** Gate silently dead (observed 2026-04-05 → 2026-06-10: ABSPATH guard in `includes/PHPStan/WordPressHookUsageProvider.php:13` made every `composer phpstan` exit 0 vacuously; 298-error real inventory accumulated undetected).
- **recovery:** Audit R-01: remove the guard from phpstan-only classes; re-run probe; re-baseline honestly; reopen any ticket whose "clean" state was vacuous.
- **confidence:** HIGH (incident-derived)
- **current status:** **PASSING** (2026-06-11: guard removed from WordPressHookUsageProvider, probe verified non-zero; 438-error honest baseline established per audit R-05 — see phpstan.neon header comment; organizer-metabox wiring bug found and fixed during triage)

## Reliability

### INV-R1 — Schema migrations are idempotent
- **statement:** Running `Schema::migrate()` against an already-migrated database is a no-op: same `nettertech_events_db_version`, no errors, no data change. (Documented property of e.g. `migrate_to_3_14_0()`; should be a tested property of every migration.)
- **source:** ISO/IEC 25010:2023 Reliability — Recoverability; ADR-016 lineage
- **fitness_function:** { categorization: continuous (integration suite), atomic, dynamic; test: `composer test:integration --filter SchemaIdempotencyTest`; expected_exit: 0 }
- **adr:** ADR-018 (pending, consolidated, before 1.1.1 — cross-reference NTE-104 migration registry)
- **owner:** maintainer
- **failure_mode:** Re-entrant migration corrupts production data on double-fire (plugin re-activation, partial upgrade).
- **recovery:** NTE-082 checkpoint recovery; restore from pre-upgrade dump.
- **confidence:** MEDIUM (property claimed in code comments; not yet gate-tested)

### INV-R2 — Interactive template markup survives the sanitization pipeline
- **statement:** Every interactive element emitted through the template pipeline (`wp_kses` + `ShortcodeOutput::get_allowlist()`) retains the tags and attributes it needs to function. A contract test renders RSVP/ticket parts and asserts the toggle button, form, and fields survive sanitization.
- **source:** incident-derived (NTE-131, 2026-06-11: inline `display:none` silently stripped → form/toggle aria state inconsistency; second incident in this class after the embed-iframe stripping fixed in 45ca9c0)
- **fitness_function:** { categorization: continuous (integration suite), atomic, dynamic; test: `composer test:integration --filter AllowlistContractTest`; expected_exit: 0 }
- **adr:** ADR-018 (pending, consolidated, before 1.1.1) (document the "no inline styles; allowlist is the contract" rule)
- **owner:** maintainer
- **failure_mode:** Markup authored against raw output silently degrades when routed through the kses pipeline; symptom appears only in rendered pages, not unit tests.
- **recovery:** Extend the allowlist deliberately or restructure markup (class-based state, not style attributes).
- **confidence:** HIGH (two incidents) — **gate does not exist yet**
